# 需求变更影响分析 Skill

## 目标

解决 AI Coding 中常见的“只改了一个页面，但相关页面、组件、数据源、类型、mock、接口、统计、筛选没有同步修改”的问题。

当用户提出需求变更、问题修改或页面调整时，本 Skill 要求 AI 在动手修改前先进行影响范围分析，然后再根据项目开发规范和架构进行联动修改。

## 触发场景

当用户提出以下内容时必须触发：

```text
1. 修改页面显示内容
2. 修改字段名称、字段含义、字段类型
3. 修改状态、枚举、标签、颜色、文案
4. 修改接口请求参数或返回结构
5. 修改表格列、详情字段、表单字段、筛选条件
6. 修改统计卡片、图表、导出字段
7. 修改权限、角色、菜单、路由
8. 修复某个页面数据不一致问题
9. 修复某个功能 bug
10. 优化现有功能逻辑
```

## 核心原则

```text
禁止直接修改单个页面。
禁止只根据当前文件判断影响范围。
禁止只改 UI 展示，不查数据来源。
禁止字段、枚举、接口、mock、类型定义不一致。
禁止在没有全局搜索的情况下重命名字段、状态、接口、组件。
```

## 修改前必须执行的流程

### 1. 识别变更类型

先判断本次修改属于哪一类：

```text
UI 展示变更
字段变更
接口变更
状态枚举变更
数据源变更
权限逻辑变更
统计逻辑变更
表单变更
筛选/排序/分页变更
导出变更
业务流程变更
路由/导航变更
```

### 2. 识别核心变更对象

必须明确：

```text
1. 涉及的业务模块是什么？
2. 涉及的业务对象是什么？
3. 涉及的字段是什么？
4. 涉及的数据源是什么？
5. 涉及的接口是什么？
6. 涉及的枚举/状态是什么？
7. 涉及的页面和组件是什么？
```

### 3. 全局搜索引用

根据变更对象进行全局搜索，至少包括：

```text
字段名
字段别名
类型名
接口名
枚举名
枚举值
状态文案
组件名
hook/composable 名
store 名
service 名
mock 名
路由名
权限标识
```

例如修改 `user.status` 时，不只搜索 `status`，还要搜索：

```text
user.status
UserStatus
USER_STATUS
statusMap
statusLabel
statusOptions
active
disabled
enabled
用户状态
启用
禁用
```

### 4. 输出影响范围清单

修改前必须输出：

```markdown
## 影响范围分析

### 变更对象
- 业务模块：
- 核心字段/接口/状态：
- 数据来源：

### 影响文件
| 类型 | 文件 | 影响说明 | 是否需要修改 |
|---|---|---|---|
| 页面 |  |  |  |
| 组件 |  |  |  |
| 类型 |  |  |  |
| 常量/枚举 |  |  |  |
| 接口服务 |  |  |  |
| 状态管理 |  |  |  |
| mock 数据 |  |  |  |
| 测试 |  |  |  |
| 文档 |  |  |  |

### 风险判断
- 是否影响多个页面：是/否
- 是否影响接口字段：是/否
- 是否影响底层数据源：是/否
- 是否影响 mock：是/否
- 是否影响测试：是/否
```

### 5. 联动修改

只有完成影响分析后，才允许修改代码。

修改时必须遵守：

```text
1. 优先修改权威数据源，而不是每个页面单独修改。
2. 如果发现多个页面重复定义相同数据，必须抽到统一位置。
3. 如果字段变化，必须同步类型、接口、mock、页面、组件、测试。
4. 如果枚举变化，必须同步显示文案、筛选选项、标签组件、统计逻辑。
5. 如果接口变化，必须同步 service、types、调用页面和错误处理。
```

## 针对不同变更类型的检查清单

### 字段变更

```text
1. 类型定义是否修改？
2. API 请求参数是否修改？
3. API 返回值处理是否修改？
4. mock 数据是否修改？
5. 表格列是否修改？
6. 表单字段是否修改？
7. 筛选条件是否修改？
8. 详情页展示是否修改？
9. 统计逻辑是否修改？
10. 导出字段是否修改？
11. 权限判断是否修改？
12. 测试用例是否修改？
```

### 状态/枚举变更

```text
1. 枚举定义是否统一？
2. 状态文案是否统一？
3. 标签颜色是否统一？
4. 筛选选项是否同步？
5. 表格展示是否同步？
6. 详情页展示是否同步？
7. 统计口径是否同步？
8. mock 数据是否同步？
9. 后端枚举是否同步？
```

### 接口变更

```text
1. service 层是否修改？
2. 请求参数类型是否修改？
3. 响应类型是否修改？
4. 调用页面是否同步？
5. 错误处理是否同步？
6. mock 是否同步？
7. 接口文档是否同步？
8. 测试是否同步？
```

### 页面展示变更

```text
1. 该展示是否有公共组件？
2. 是否多个页面展示同一字段？
3. 是否应通过统一 formatter 处理？
4. 是否涉及空状态/错误状态/加载状态？
5. 是否影响移动端/响应式布局？
```
