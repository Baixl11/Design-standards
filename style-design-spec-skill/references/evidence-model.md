# 证据与溯源模型

对每个数值、视觉属性、行为和建议单独记录证据。不要用章节级标签代替逐项溯源。

## 记录原则

- 为原始证据分配稳定 ID，格式使用 `E-001`、`E-002`，并匹配 `^E-[0-9]{3,}$`。
- 让一个记录只支持一个可验证结论；多个结论分别建项。
- 使用 `status` 记录 provenance 类型，并与 `confidence` 分开填写。不要根据类型自动推导置信度。
- 记录采集上下文，包括对象、版本、页面、视口、主题、状态和输入模态。
- 保留原始截图、节点、选择器、代码位置或操作步骤的定位信息。
- 无法访问或验证时明确留空，不要补写看似精确的值。

## Provenance Status

只使用以下值：

| 值 | 使用条件 |
| --- | --- |
| `measured` | 使用 DOM、设计工具、代码、标尺或自动化工具直接取得几何、排版、时长等数值。 |
| `sampled` | 从渲染结果、截图、像素或多次样本中取色或取样；同时记录采样方法和缩放条件。 |
| `observed` | 直接看见界面属性或操作结果，但没有可靠的精确数值。 |
| `inferred` | 根据多个证据推导规律、语义或未显式声明的关系；写明推导过程。 |
| `adapted` | 为目标产品、平台或无障碍要求主动调整；不要表述为参考对象的原始事实。 |

同一结论只能指定一个 `status`。除 `adapted` 外，至少在 `evidenceIds` 中引用一个上游证据；`adapted` 可不引用证据，但必须填写 `rationale`。

## Confidence

独立使用 `high`、`medium` 或 `low`：

- `high`：来源直接、上下文明确，且重复检查一致。
- `medium`：来源直接但上下文或精度受限，或只有单次可靠观察。
- `low`：信息不完整、比例不确定、样本少，或包含较强推断。

始终填写 `confidenceReason`。例如，截图缩放未知时，即使 `status` 为 `sampled`，也应降低置信度。

## 逐项记录格式

使用下列字段；在 Markdown 中可用同名表格列，在 JSON 中保持同名键：

```yaml
claimId: C-001
subject: component.button.primary
property: border-radius
value: 8px
status: measured
confidence: high
confidenceReason: 同一版本的三个实例由检查工具取得相同值
evidenceIds: [E-007, E-008]
scope:
  source: 目标应用
  version: 已观察版本或提交号
  location: 页面、节点、选择器或文件位置
  viewport: 视口尺寸或 N/A
  theme: light
  state: default
  input_modality: pointer
method: 使用的工具和操作
captured_at: ISO-8601 时间
notes: 可选限制
```

示例中的值只说明字段结构，不得作为默认设计值复制。

## 原始证据索引

为每个 `evidenceId` 建立索引，并至少记录：

- `type`：截图、录屏、DOM、设计节点、代码、文档或访谈。
- `locator`：可复查的文件路径、URL、节点 ID、选择器或时间戳。
- `context`：版本、页面、视口、主题、状态和输入模态。
- `method`：采集工具、步骤及可能误差。
- `captured_at`：采集时间。

不要把账号、密钥、个人信息或未脱敏生产数据写入索引。

## 冲突处理

发现冲突时按顺序执行：

1. 检查版本、页面、视口、主题、状态、平台和输入模态是否相同。
2. 在相同上下文重复采集，排除缓存、缩放、动画中间帧和采样误差。
3. 若差异由上下文造成，保留为不同条件下的独立规则。
4. 若存在明确权威来源，选择该结论，并记录采用理由和全部被拒绝的 `evidenceIds`。
5. 若仍无法裁决，将 `resolution` 标为 `unresolved_conflict`，保留双方证据，不生成确定数值或代码。

不要静默覆盖冲突项。不要用平均值伪造统一规则。

## 发布检查

- 检查除 `adapted` 外的每个确定结论是否至少引用一个 `evidenceId`。
- 检查无证据的 `adapted` 项是否填写 `rationale` 和明确 `scope`。
- 检查每个推断是否说明依据，每个适配是否说明目标约束。
- 检查置信度是否独立填写并附理由。
- 检查证据定位是否可复查，冲突是否已保留处理记录。
- 将缺失证据的内容列入待补采集项，不要混入已确认规范。
