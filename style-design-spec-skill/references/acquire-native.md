# 桌面与移动端采集

仅在目标包含桌面应用、移动应用、安装包、设备截图或录屏时读取本文件。优先检查安全边界和可运行能力。

## 能力预检

记录以下能力及结果：

| 能力 | 桌面端检查 | 移动端检查 |
| --- | --- | --- |
| 运行环境 | OS、版本、架构、DPI、沙箱或虚拟机 | OS、版本、设备/模拟器、屏幕密度、安全区 |
| 产物可信度 | 来源、签名、哈希、最低权限 | 商店来源或签名、包名、权限清单 |
| 检查能力 | 窗口调整、键盘、指针、可访问性检查器 | 旋转、软键盘、触控、可访问性检查器 |
| 资料可用性 | 源代码、设计稿、截图、录屏、版本号 | 源代码、Figma、截图、录屏、构建版本 |
| 身份验证 | 现有测试会话、离线演示数据 | 现有测试会话、测试租户、离线演示数据 |

- 未确认来源、签名或影响范围时，不得安装或运行未知产物。
- 需要安装时，使用隔离测试环境和最低权限；不得关闭系统防护、越狱、Root 或绕过证书校验。
- 不得索取生产密码、恢复码、支付信息或真实客户数据。优先使用用户已有会话、测试账号和合成数据。
- 不得批准与目标流程无关的相机、麦克风、通讯录、定位、文件或辅助功能权限。
- 捕获前清理通知、剪贴板提示、账号、设备标识、位置和个人内容。

## 证据层级

按目标属性使用证据：

1. **真实运行证据**：可访问性树、布局检查器、窗口/设备测量、实际键盘和触控交互。用它确认当前构建的行为与语义。
2. **版本匹配的结构资料**：Figma 变量与组件、源代码 token、平台资源和组件实现。用它确认规范意图，不得替代运行验证。
3. **原始截图**：用于采样与静态布局观察；必须记录设备、分辨率、缩放、方向、主题和页面状态。
4. **原始录屏**：用于流程、手势、状态转换和动效；不得从压缩视频宣称精确尺寸或颜色。
5. **文字说明**：仅作为范围和操作线索。

若运行构建与 Figma 或代码冲突，分别记录“当前构建”和“规范意图”，不得自行选一个覆盖另一个。

## 桌面端采集

1. 记录 OS、应用版本、窗口状态、显示缩放和输入方式。
2. 覆盖最小可用窗口、常用窗口、最大化、多显示器或高 DPI 中实际可测的范围。
3. 记录窗口缩放时的重排、最小尺寸、截断、滚动和面板折叠，不得从单个尺寸推断断点。
4. 检查菜单栏、标题栏、系统菜单、右键菜单、对话框、拖放、快捷键和退出确认。
5. 完成纯键盘主流程，检查焦点顺序、焦点可见性、焦点陷阱和窗口切换后的焦点恢复。
6. 仅对支持指针的平台记录 hover；同时检查触控板、触摸屏或键盘等可用输入方式。

## 移动端采集

1. 记录设备、OS、构建版本、屏幕密度、方向、字体缩放、显示缩放和系统导航模式。
2. 覆盖安全区、状态栏、系统导航、刘海/挖孔、圆角、软键盘和底部手势区域。
3. 检查竖屏和横屏中产品实际支持的方向；不支持时记录明确行为。
4. 检查点击、长按、滑动、拖动、返回手势和中断恢复。不得为纯触控交互编造 hover 状态。
5. 检查动态字体、文本放大、屏幕阅读器名称、焦点顺序、触控目标间距和仅手势操作的替代路径。
6. 检查离线、弱网、权限拒绝、来电/通知中断、后台恢复和会话过期等适用状态。
7. 分别记录 iOS、Android 和跨平台实现差异；不得用统一的 `44px` 规则替代平台规范和实测结果。

## 采集与标注

- 为每份证据分配 `evidenceId`，记录版本、页面、状态、主题、语言、设备/窗口、输入方式、时间和采集方法；让逐项结论通过 `evidenceIds` 引用它。
- 为每个结论标注 `measured`、`sampled`、`observed`、`inferred` 或 `adapted`。
- 只覆盖实际出现或项目明确需要的组件。平台补全项必须标为 `adapted`。
- 对关键流程建立状态矩阵，至少包含正常、加载、空、错误、禁用和权限拒绝中适用的状态。

## 降级规则

- `verified`：目标构建可运行，范围内关键流程、平台状态、输入方式和布局变化均有直接可重复证据，且质量门禁通过。
- `partial`：构建可运行或存在结构证据，但仍缺少部分页面、权限、设备、主题、输入方式或异常状态。
- `draft`：无法安全运行，仅有截图、视频、文字或无法对应版本的设计稿/代码。

无法安全运行时，停止安装或执行，但继续整理可用材料。列出受限范围、风险、替代证据和完成验证所需的最小条件；不得把草案描述成完整采集。
