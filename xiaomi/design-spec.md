## 5. 设计定位

本规范以 Xiaomi HyperOS 3 的公开产品展示为当前范围：浅色中性信息骨架、圆角多尺寸组件、彩色内容和图标、深色即时活动层，以及跨设备连续任务。MiSans Global 支持全球多语言与可变字体。官方未公开完整 UI token，因此所有精确数值均为独立项目适配。

| 规则 | 可观察/可验收表现 | 来源类型 | 置信度 | 证据 |
|---|---|---|---|---|
| 中性骨架 + 彩色内容 | 页面基底克制，应用图标与组件内容可更彩色和个性化。 | `inferred` | Medium | E-002 |
| 多尺寸组件 | 信息组件根据尺寸重组内容，存在方形、横向与组合式密度。 | `observed` | High | E-001, E-002 |
| 连续即时活动 | 持续状态在紧凑胶囊、展开内容与浮窗间保持对象和任务连续。 | `inferred` | Medium | E-001, E-003 |
| 跨终端排版 | 字体与信息层级面向多语言和跨设备一致阅读。 | `observed` | High | E-004, E-005 |

### 适用场景

- 智能设备生态、个人效率、媒体、家庭控制和需要跨设备连续性的应用。
- 强调主屏组件、即时活动、个性化布局和轻量浮窗的移动产品。
- 需要全球多语言字体与相对亲和、彩色但不杂乱的界面。

### 不宜直接套用

- 直接复制 HyperOS 图标、壁纸、组件截图、商标或系统文案。
- 把官方营销图采样成所谓完整品牌 token。
- 将平板分屏比例、动画数量或单一主屏样本扩张为所有 Web/移动规则。

## 6. 设计原则

| 原则 | 可执行规则 | 例外 | 来源与置信度 |
|---|---|---|---|
| 信息先清楚 | 浅色中性表面与清晰深色排版承载核心内容，彩色用于应用身份与高价值状态。 | 深色即时活动层可反转文字，但需独立测对比。 | `inferred`, Medium, E-002, E-003 |
| 状态保持连续 | 同一任务从胶囊到展开层或浮窗时保持内容身份、位置关系和进度。 | 平台不支持浮窗时退化为抽屉或详情页。 | `inferred`, Medium, E-001, E-003 |
| 组件允许个性化 | 尺寸、布局和内容密度可变化，但基础网格、阅读顺序和状态语义稳定。 | 高风险和系统状态不因皮肤改变语义。 | `observed`, High, E-001, E-002 |
| 全球排版 | 优先 MiSans 或经许可的全球字体并使用可变字重建立层级。 | 无法加载时使用稳定 CJK/system fallback，不以位图文字替代。 | `observed`, High, E-004, E-005 |

## 8. Token 架构

`design-tokens.json` 是本实施包的结构化单一事实源：

1. `primitive.*` 保存颜色、间距、圆角、排版、时长和效果原值。
2. `semantic.*` 按背景、表面、文本、操作、反馈、焦点和形状角色引用 primitive。
3. `component.*` 为按钮、输入框和卡片绑定 semantic 角色。
4. 主题切换只替换 semantic 映射；未知主题值不写入空 token。
5. 所有叶节点都有 `status`、`evidenceIds`、`confidence`、`scope` 和 `rationale`。

当前 JSON 是跨平台起始源；CSS、Tailwind、Compose、SwiftUI 等映射应在技术栈和版本确定后由该源单向生成。

## 9. 组件规范

### Widget / 信息组件

组件级 provenance：`status=adapted`；`confidence=medium`；`confidenceReason=来源支持风格或交互原则，结构和精确实现值是跨平台起始适配，尚无目标产品运行时证据。`；`evidenceIds=E-001,E-002,E-003,E-004,E-005,E-090,E-091`；`scope=Web 与移动端参考；浅色起始主题；键盘、指针、触控和辅助技术`；`method=公开规范归纳后进行独立项目适配`；`captured_at=2026-07-14T10:19:53+08:00`；`rationale=把官方观察到的多尺寸信息组件转换为独立项目的可访问组件契约。`。

| 项目 | 规范 | 来源与证据 |
|---|---|---|

## 11. 响应式与输入模态

- 以内容和任务触发行为变化：导航拥挤时改型、列宽不足时重排、操作过密时按优先级分层；阈值由目标项目记录。
- 触控界面不依赖 hover；精细指针的 hover 只加强默认可见线索。
- 交互目标起始值采用 44px；Web 合规仍须逐项核对 WCAG 2.2 的 24×24 CSS px 基线及例外。
- 200% 文本缩放与约 320 CSS px reflow 时，不丢失标签、错误、操作、当前状态与恢复路径。
- 使用逻辑方向属性；RTL 只镜像具有方向语义的布局和图标。
- 1:9 只是在支持设备上的平板分屏展示，不能当作 Web 或全部产品的固定比例。
- 切换屏幕、窗口或方向时保留浏览位置、输入、媒体进度和任务状态。

## 12. 主题、国际化与极端内容

- 浅色、深色和高对比主题分别映射 semantic token；不得直接反相颜色、阴影、图片或材质。
- 响应 prefers-color-scheme、prefers-contrast、forced-colors、prefers-reduced-motion；透明材质还应处理 prefers-reduced-transparency。
- 使用真实 CJK、拉丁长词、阿拉伯语 RTL、日期、数字、货币和 30%–50% 文案膨胀测试。
- 按钮与标签允许换行或自适应宽度，不通过缩小字号或无提示省略关键动作解决溢出。
- 公开样本不足以证明完整 HyperOS 深色主题；为项目单独建立 light/dark/high-contrast semantic 映射。
- 即时活动深色胶囊与普通深色主题不是同一概念，不能共享未经验证的全部色值。

## 16. 实现与验收说明

- 开发只消费 `design-tokens.json`，不要在组件中另写同义颜色、尺寸或时长。
- 实现前先把目标产品的页面、组件、状态、主题和输入模态填入覆盖矩阵。
- 实现后执行 `design-review-checklist.md`；没有证据的项目保持 `Not tested`。
- Web 至少验证 320 CSS px reflow、200% 文本缩放、键盘全流程、读屏状态公告和 WCAG 2.2 AA 对比度。
- 视觉回归应覆盖默认、focus-visible、disabled、loading、empty、error、长文本、深色或高对比等适用状态。
- 若目标平台提供原生组件和主题能力，优先遵循对应平台规范；本包只定义风格层，不替代平台交互契约。
