# Design Review Checklist

## 1. 采集来源检查

```text
[ ] 页面设计是否基于真实采集数据？
[ ] 是否标注了目标对象和采集来源？
[ ] 是否区分了真实采集、观察估算和适配建议？
[ ] 是否存在未说明来源的精确数值？
[ ] 是否存在把估算值写成确定值的问题？
[ ] 是否存在未访问目标对象就生成完整规范的问题？
```

## 2. 整体风格检查

```text
[ ] 页面是否符合目标风格定位？
[ ] 页面视觉气质是否与 design-spec.md 一致？
[ ] 是否存在明显偏离参考风格的视觉元素？
[ ] 页面是否保持专业、统一、克制？
[ ] 是否避免了过度装饰和无意义动效？
```

## 3. 色彩检查

```text
[ ] 是否使用了 design-tokens.md 中定义的颜色？
[ ] 是否存在未定义的新颜色？
[ ] 主按钮颜色是否统一？
[ ] 激活状态颜色是否统一？
[ ] 错误、成功、警告、信息状态色是否统一？
[ ] 背景色是否符合页面层级？
[ ] 文本颜色是否符合主次层级？
```

## 4. 字体检查

```text
[ ] 是否使用统一字体家族？
[ ] 页面标题字号是否符合规范？
[ ] 模块标题字号是否符合规范？
[ ] 正文字号是否符合规范？
[ ] 辅助说明字号是否符合规范？
[ ] 字重是否符合信息层级？
[ ] 是否存在过多字号层级？
```

## 5. 间距检查

```text
[ ] 页面外边距是否统一？
[ ] 模块之间的间距是否统一？
[ ] 卡片内边距是否统一？
[ ] 表单项间距是否统一？
[ ] 按钮内边距是否统一？
[ ] 表格单元格间距是否统一？
[ ] 是否遵循 4px / 8px 间距体系？
```

## 6. 圆角与阴影检查

```text
[ ] 按钮圆角是否统一？
[ ] 输入框圆角是否统一？
[ ] 卡片圆角是否统一？
[ ] 弹窗圆角是否统一？
[ ] 阴影是否克制？
[ ] 是否存在过重、过乱的阴影？
[ ] 是否存在多个不一致的圆角值？
```

## 7. 组件一致性检查

```text
[ ] Button 是否符合组件规范？
[ ] Input 是否符合组件规范？
[ ] Select 是否符合组件规范？
[ ] Table 是否符合组件规范？
[ ] Card 是否符合组件规范？
[ ] Modal 是否符合组件规范？
[ ] Drawer 是否符合组件规范？
[ ] Tabs 是否符合组件规范？
[ ] Tag 是否符合组件规范？
[ ] Alert 是否符合组件规范？
[ ] Empty 是否符合组件规范？
[ ] Loading 是否符合组件规范？
[ ] Sidebar 是否符合组件规范？
[ ] Topbar 是否符合组件规范？
[ ] Form 是否符合组件规范？
```

## 8. 页面布局检查

```text
[ ] 页面结构是否符合对应页面模板？
[ ] 页面信息层级是否清晰？
[ ] 主要操作是否放在用户容易发现的位置？
[ ] 搜索、筛选、操作区是否布局合理？
[ ] Dashboard 指标卡是否统一？
[ ] 列表页是否具备清晰的筛选、表格和分页结构？
[ ] 详情页是否具备清晰的信息分组？
[ ] 表单页是否具备清晰的填写路径？
[ ] 卡片、列表项和导航项宽度是否适配父容器？
[ ] 是否存在文字、图标、徽标、按钮互相挤压或重叠？
[ ] 列表项中的时间、角标、操作按钮是否不会挤压主文本？
```

## 9. 交互状态检查

```text
[ ] 按钮是否有 hover 状态？
[ ] 按钮是否有 active 状态？
[ ] 按钮是否有 disabled 状态？
[ ] 按钮是否有 loading 状态？
[ ] 按钮和底部导航项是否有稳定宽高，状态变化时不改变布局尺寸？
[ ] 选中态和 hover 态边框是否使用与背景相近的低透明颜色，而不是突兀高对比描边？
[ ] 输入框是否有 focus 状态？
[ ] 表单错误提示是否清晰？
[ ] 是否有空状态？
[ ] 是否有加载状态？
[ ] 是否有错误状态？
[ ] 操作成功后是否有反馈？
```

## 10. 响应式检查

```text
[ ] 1440px 桌面端是否显示正常？
[ ] 1920px 大屏是否显示正常？
[ ] 平板宽度下侧边栏是否可用？
[ ] 移动端是否避免横向溢出？
[ ] 表格在小屏幕下是否有合理处理？
[ ] 操作按钮在小屏幕下是否合理收纳？
[ ] 430px 和 390px 移动端宽度下是否显示正常？
[ ] 所有文本是否没有遮挡、重叠、异常换行或被角标覆盖？
[ ] 所有按钮、图标按钮、底部导航项点击区域是否不小于 44px 高？
[ ] 页面是否经过浏览器截图或视觉检查确认，而不只做代码静态判断？
```

## 11. 代码实现检查

```text
[ ] 是否优先使用 design-tokens.md 中的 token？
[ ] 是否避免在页面中写大量零散样式？
[ ] 是否避免硬编码颜色？
[ ] 是否避免硬编码间距？
[ ] 是否避免硬编码圆角？
[ ] 是否复用了已有组件？
[ ] 新增组件是否符合设计规范？
[ ] 是否存在与设计规范冲突的 className？
[ ] 是否存在重复样式？
```

## 12. AI Coding 自检提示词

```text
请根据 design-spec.md、design-tokens.md 和 design-review-checklist.md 检查当前页面。

重点检查：

1. 当前页面是否符合目标风格定位；
2. 是否使用了统一的颜色、字号、间距、圆角和阴影；
3. 是否存在未定义的临时样式；
4. 是否存在与设计规范冲突的组件；
5. 页面布局是否符合对应页面模板；
6. 按钮、表单、表格、卡片、弹窗等组件是否一致；
7. hover、active、disabled、loading、empty、error 等状态是否完整；
8. 是否优先使用 design tokens，而不是在页面中写死样式；
9. 是否存在视觉风格割裂的问题；
10. 响应式下是否没有横向溢出、文字遮挡、按钮挤压、角标覆盖或选中态边框突兀；
11. 如果发现问题，请列出问题位置、原因和修改建议。
```
