## 2. 范围与限制

### 已覆盖

- 公开材料中的风格定位、原则和使用边界（E-001、E-002、E-003、E-004）。
- 面向独立项目的颜色、排版、间距、形状、层级、动效与语义 token 起始方案。
- 代表性组件：实体按钮、旋钮 / 滑块、开关 / 指示灯、材质面板 / 仪表。
- Web WCAG 2.2 AA、用户偏好、键盘/触控/辅助技术和国际化的适配要求。

### 未覆盖

- 目标产品、用户任务、技术栈、组件库、真实页面、运行时样式和设计文件。
- 品牌或平台未公开的内部 token、完整组件状态、动效实现与版本差异。
- 真实深浅主题、高对比模式、断点、设备安全区、性能与视觉回归结果。

### 使用限制

- 只学习可迁移规律，不复制 Logo、商标、专有字体字形、图标、插画、产品图或品牌文案。
- 来源为公开文档和研究，不是目标应用的 DOM、代码、设计节点或像素测量。
- 精确起始值全部标为 adapted；落地后必须按具体前景/背景、状态和平台复测。

## 5. 设计定位

拟物化不是“加纹理和阴影”，而是用现实对象、材料或操作模型帮助理解数字功能。只有当现实线索与真实可用动作、状态或概念模型对应时才有意义；纯装饰性写实效果不能冒充可用性。

| 规则 | 可观察/可验收表现 | 来源类型 | 置信度 | 证据 |
|---|---|---|---|---|
| 单一隐喻 | 一个界面区域采用同一对象、材质、光源和受力逻辑。 | `inferred` | Medium | E-002, E-003 |
| 功能对应 | 高光、把手、凹槽、旋钮和按钮只在确有相应动作或状态时出现。 | `observed` | High | E-003 |
| 数字优先 | 保留搜索、撤销、批量、直接输入和键盘操作，不复制现实世界的低效限制。 | `inferred` | High | E-002, E-004 |

### 适用场景

- 音乐、仪表、创作工具、模拟器和具备明确物件心智模型的垂直场景。
- 需要帮助新手理解新数字概念，且现实对象对目标用户确实熟悉。
- 品牌展示或低频体验中少量使用一致材质强化情绪。

### 不宜直接套用

- 高密度企业后台和大量重复数据表格。
- 目标用户不熟悉所选现实对象或文化隐喻。
- 仅为怀旧而堆叠木纹、皮革、金属和装饰螺丝的界面。

## 6. 设计原则

| 原则 | 可执行规则 | 例外 | 来源与置信度 |
|---|---|---|---|
| 隐喻服务理解 | 先定义现实对象与数字任务的映射，再设计材质。 | 成熟数字模式更清楚时优先平台惯例。 | `observed`, High, E-001, E-004 |
| 线索必须真实 | 看起来可按、可拖、可翻的元素必须支持对应动作。 | 纯装饰明确移出交互和焦点顺序。 | `observed`, High, E-003 |
| 一致光源与受力 | 同一层级保持统一光源、投影方向和 pressed 反馈。 | 不同材质可有不同粗糙度，但不能改变空间逻辑。 | `inferred`, Medium, E-002 |
| 不要复制现实限制 | 数字操作可以更快、更可搜索、更可撤销。 | 专业模拟训练若要求物理忠实，可保留经验证的限制。 | `observed`, High, E-002 |

### 7.5 图标、图像与品牌资产

- 材质纹理必须可授权、可压缩且不包含品牌专有图案。
- 同一界面不混用木、皮革、玻璃、金属等多个无关隐喻。
- 对象图标若年代化或文化依赖，必须配文字并验证目标用户理解。

## 8. Token 架构

`design-tokens.json` 是本实施包的结构化单一事实源：

1. `primitive.*` 保存颜色、间距、圆角、排版、时长和效果原值。
2. `semantic.*` 按背景、表面、文本、操作、反馈、焦点和形状角色引用 primitive。
3. `component.*` 为按钮、输入框和卡片绑定 semantic 角色。
4. 主题切换只替换 semantic 映射；未知主题值不写入空 token。
5. 所有叶节点都有 `status`、`evidenceIds`、`confidence`、`scope` 和 `rationale`。

当前 JSON 是跨平台起始源；CSS、Tailwind、Compose、SwiftUI 等映射应在技术栈和版本确定后由该源单向生成。

## 9. 组件规范

### 实体按钮

组件级 provenance：`status=adapted`；`confidence=medium`；`confidenceReason=来源支持风格或交互原则，结构和精确实现值是跨平台起始适配，尚无目标产品运行时证据。`；`evidenceIds=E-001,E-002,E-003,E-004,E-090,E-091`；`scope=Web 与移动端参考；浅色起始主题；键盘、指针、触控和辅助技术`；`method=公开规范归纳后进行独立项目适配`；`captured_at=2026-07-14T10:19:53+08:00`；`rationale=将物理按压隐喻用于真实动作，并保留数字平台的语义和恢复能力。`。

| 项目 | 规范 | 来源与证据 |
|---|---|---|
| 用途与边界 | 用受力和材质线索表达可按压动作。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| Anatomy | 基座、面层、标签；高光、边缘和投影仅为视觉部位。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| Variants 与 sizes | primary / secondary / destructive；形状由统一物件隐喻决定。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| 适用状态 | raised、hover（适用时）、focus-visible、pressed、disabled、loading；loading 不等于持续 pressed。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| 内容与溢出 | 可见文字优先，装饰图标不替代动作名称。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| 鼠标、键盘与触控 | 指针/触控按下即时反馈；Enter/Space 激活；松开或取消时恢复。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| 响应式行为 | 小屏简化纹理和高光，不等比缩成不可读微型物件。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| 无障碍 | focus ring 独立于高光/投影；按下状态不只靠位移；高风险动作可恢复。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |
| Tokens | component.button.primary.*；primitive.effect.shadowRaised；semantic.color.focus。 | `adapted`, Medium, E-001, E-002, E-003, E-004, E-090, E-091 |

## 11. 响应式与输入模态

- 以内容和任务触发行为变化：导航拥挤时改型、列宽不足时重排、操作过密时按优先级分层；阈值由目标项目记录。
- 触控界面不依赖 hover；精细指针的 hover 只加强默认可见线索。
- 交互目标起始值采用 44px；Web 合规仍须逐项核对 WCAG 2.2 的 24×24 CSS px 基线及例外。
- 200% 文本缩放与约 320 CSS px reflow 时，不丢失标签、错误、操作、当前状态与恢复路径。
- 使用逻辑方向属性；RTL 只镜像具有方向语义的布局和图标。
- 不能把完整现实对象等比缩成微型；优先删除次要纹理并保留功能映射。
- 拟物手势必须提供可见控制或键盘等价操作。

## 12. 主题、国际化与极端内容

- 浅色、深色和高对比主题分别映射 semantic token；不得直接反相颜色、阴影、图片或材质。
- 响应 prefers-color-scheme、prefers-contrast、forced-colors、prefers-reduced-motion；透明材质还应处理 prefers-reduced-transparency。
- 使用真实 CJK、拉丁长词、阿拉伯语 RTL、日期、数字、货币和 30%–50% 文案膨胀测试。
- 按钮与标签允许换行或自适应宽度，不通过缩小字号或无提示省略关键动作解决溢出。
- 暗色材质需重新设计光照、纹理与边界，禁止对浅色纹理直接反相。
- 对比度按纹理最差位置测量；不满足时在文字和图标下加实色衬底。

### 反模式

- 不可点击装饰看起来像按钮、把手或标签。
- 多种无关材质和错误光源混搭。
- 物理隐喻阻止搜索、撤销、批量或直接输入。
- 只靠灯色、指针位置或声音表达状态。
- 把文字烘焙进纹理图片，导致缩放、本地化和读屏失败。

## 16. 实现与验收说明

- 开发只消费 `design-tokens.json`，不要在组件中另写同义颜色、尺寸或时长。
- 实现前先把目标产品的页面、组件、状态、主题和输入模态填入覆盖矩阵。
- 实现后执行 `design-review-checklist.md`；没有证据的项目保持 `Not tested`。
- Web 至少验证 320 CSS px reflow、200% 文本缩放、键盘全流程、读屏状态公告和 WCAG 2.2 AA 对比度。
- 视觉回归应覆盖默认、focus-visible、disabled、loading、empty、error、长文本、深色或高对比等适用状态。
- 若目标平台提供原生组件和主题能力，优先遵循对应平台规范；本包只定义风格层，不替代平台交互契约。
