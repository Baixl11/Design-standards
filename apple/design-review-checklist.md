# Apple Design Style Review Checklist

## 1. 采集来源检查

```text
[ ] 页面设计是否基于 Apple 官方页面、HIG、设计资源或明确参考截图？
[ ] 是否标注了真实采集、观察估算和适配建议？
[ ] 是否存在未说明来源的精确色值、字号、间距或圆角？
[ ] 是否把估算值写成了确定值？
[ ] 是否复制了 Apple Logo、产品图、商标、专有插画或专有图标？
[ ] 如果用于 iOS/macOS 原生应用，是否复核了对应平台 HIG？
```

## 2. 整体风格检查

```text
[ ] 页面是否保持克制、清晰、轻量、内容优先？
[ ] 是否避免了大面积装饰、复杂纹理和重渐变？
[ ] 主内容是否足够突出，辅助信息是否安静？
[ ] 页面是否有充足留白，而不是被卡片和边框塞满？
[ ] 是否避免了过重阴影、过多色块和无意义动效？
[ ] 营销页与后台页是否按场景调整了信息密度？
```

## 3. 色彩检查

```text
[ ] 是否优先使用 design-tokens.md 中的颜色？
[ ] 主色是否使用 #0071E3 或其 token？
[ ] 主文本是否使用 #1D1D1F，次级文本是否使用 #6E6E73 / #86868B？
[ ] 页面背景是否使用 #FFFFFF / #F5F5F7 的浅色层级？
[ ] 深色模式是否使用 #000000 / #161617 / #F5F5F7 的深色层级？
[ ] 是否存在未定义的新颜色？
[ ] 状态色是否只用于状态反馈，不用于普通装饰？
[ ] 边框和分割线是否足够轻？
```

## 4. 字体检查

```text
[ ] 是否使用 SF Pro / system / Helvetica Neue / PingFang SC 字体栈？
[ ] 正文和按钮是否接近 16px / 17px？
[ ] 导航、脚注等弱信息是否使用 12px 到 14px？
[ ] 标题是否使用 600 / 700 字重？
[ ] 是否避免了过多字号层级？
[ ] 是否保持 letter-spacing 为 0？
[ ] 大标题在移动端是否降级，避免换行难读？
```

## 5. 间距检查

```text
[ ] 是否遵循 4px / 8px 间距体系？
[ ] 页面外边距是否统一？
[ ] 营销页是否有足够的区块留白？
[ ] 后台页是否避免过度留白导致效率下降？
[ ] 卡片内边距是否统一为 24px / 32px 等 token？
[ ] 表单项间距是否统一？
[ ] 按钮内边距是否接近 11px 21px 或使用 token？
[ ] 表格单元格间距是否一致？
```

## 6. 圆角与阴影检查

```text
[ ] 主按钮是否使用胶囊圆角？
[ ] 输入框、卡片、弹窗的圆角是否来自 token？
[ ] 同一页面是否避免混用过多圆角值？
[ ] 默认卡片是否避免重阴影？
[ ] 弹窗阴影是否清晰但不厚重？
[ ] hover 阴影是否轻微，不造成跳动感？
```

## 7. 组件一致性检查

```text
[ ] Button 是否符合主色、白字、17px、胶囊圆角规范？
[ ] Input 是否有默认、focus、error、disabled 状态？
[ ] Select 是否和 Input 高度、圆角、边框一致？
[ ] Table 是否使用弱分割线、清晰 hover、合理行高？
[ ] Card 是否保持干净背景、统一圆角和内边距？
[ ] Modal 是否有清晰标题、关闭按钮、遮罩和焦点处理？
[ ] Drawer 是否有固定标题/操作区和可滚动内容区？
[ ] Tabs 是否轻量，激活态不过度装饰？
[ ] Tag 是否低饱和、低噪声？
[ ] Alert 是否清楚说明状态和处理方式？
[ ] Empty 是否有短文案和下一步动作？
[ ] Loading 是否保留布局稳定？
[ ] Sidebar 是否克制、清晰、当前项可辨认？
[ ] Topbar 是否轻量，不占用过多视觉中心？
[ ] Form 是否具备明确填写路径和错误反馈？
```

## 8. 页面布局检查

```text
[ ] 首屏是否有明确主标题、说明和主操作？
[ ] 产品/内容是否是视觉中心，而不是装饰背景？
[ ] 是否避免在一个屏幕里表达太多主题？
[ ] SaaS 页面是否有清晰标题、工具区、内容区和操作区？
[ ] 列表页是否具备搜索、筛选、表格、分页结构？
[ ] 详情页是否有清晰信息分组？
[ ] 设置页是否有清晰分类和单项说明？
[ ] 移动端是否转为单列布局？
[ ] 卡片、列表项和导航项宽度是否适配父容器？
[ ] 是否存在文字、图标、徽标、按钮互相挤压或重叠？
[ ] 列表项中的时间、角标、操作按钮是否不会挤压主文本？
```

## 9. 交互状态检查

```text
[ ] 按钮是否有 hover 状态？
[ ] 按钮是否有 active 状态？
[ ] 按钮是否有 disabled 状态？
[ ] 按钮是否有 loading 状态，且宽度不跳动？
[ ] 按钮和底部导航项是否有稳定宽高，状态变化时不改变布局尺寸？
[ ] 选中态和 hover 态边框是否使用与背景相近的低透明颜色，而不是突兀高对比描边？
[ ] 输入框是否有 visible focus 状态？
[ ] 可点击卡片是否有轻微 hover 反馈？
[ ] 表格行是否有 hover 状态？
[ ] 表单错误提示是否靠近字段并说明原因？
[ ] 成功、错误、空状态和加载状态是否完整？
[ ] 键盘焦点是否可见？
```

## 10. 动效检查

```text
[ ] 常规过渡是否控制在 160ms 到 220ms？
[ ] 弹窗、抽屉、菜单进入是否自然且不拖沓？
[ ] 是否使用统一 easing token？
[ ] 是否避免无意义循环动画？
[ ] 动效是否不会影响阅读和操作效率？
[ ] 减弱动效偏好下是否可正常使用？
```

## 11. 响应式检查

```text
[ ] 1440px 桌面端是否显示正常？
[ ] 1920px 大屏是否没有过度拉伸？
[ ] 1024px 平板下侧边栏是否可折叠或仍可用？
[ ] 768px 以下是否转为合理单列？
[ ] 430px 和 390px 移动端宽度下是否显示正常？
[ ] 移动端是否避免横向溢出？
[ ] 表格在小屏幕下是否有横向滚动或卡片化方案？
[ ] 按钮和操作区在小屏幕下是否合理收纳？
[ ] 大标题在小屏幕下是否降级？
[ ] 所有文本是否没有遮挡、重叠、异常换行或被角标覆盖？
[ ] 所有按钮、图标按钮、底部导航项点击区域是否不小于 44px 高？
[ ] 页面是否经过浏览器截图或视觉检查确认，而不只做代码静态判断？
```

## 12. 代码实现检查

```text
[ ] 是否优先使用 design-tokens.md 中的 token？
[ ] 是否避免硬编码颜色？
[ ] 是否避免硬编码间距？
[ ] 是否避免硬编码圆角？
[ ] 是否避免硬编码阴影？
[ ] 是否复用了已有组件？
[ ] 新增组件是否符合 Apple 风格规范？
[ ] 是否支持深浅主题？
[ ] 是否存在与规范冲突的 className？
[ ] 是否存在重复样式或临时样式？
[ ] 是否没有直接引入 Apple 专有品牌素材？
```

## 13. AI Coding 自检提示词

```text
请根据 apple-design-style/design-spec.md、design-tokens.md 和 design-review-checklist.md 检查当前页面。

重点检查：
1. 页面是否呈现 Apple 风格的克制、清晰、内容优先；
2. 是否使用 #0071E3、#1D1D1F、#6E6E73、#F5F5F7 等规范 token；
3. 主按钮是否符合 17px、11px 21px、胶囊圆角；
4. 字体是否使用 SF Pro / system / Helvetica Neue / PingFang SC 字体栈；
5. 是否存在未定义的临时颜色、字号、间距、圆角或阴影；
6. 组件状态是否完整，包括 hover、focus、active、disabled、loading、empty、error；
7. 布局是否根据营销页或后台页场景调整了信息密度；
8. 响应式下是否没有横向溢出、文字遮挡或按钮挤压；
9. 是否没有复制 Apple Logo、产品图、商标或专有素材；
10. 如果发现问题，请列出位置、原因和修改建议。
```
