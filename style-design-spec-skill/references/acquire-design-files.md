# 结构化设计文件采集

仅在来源包含 Figma、Sketch、MasterGo、设计变量导出或其他结构化设计文件时读取本文件。将设计文件视为设计意图证据，不默认视为线上实现事实。

## 能力与范围预检

先确认：

- 是否有可读取的文件、页面、节点或组件链接，而不是只有文件首页。
- 是否具有所需库、分支、版本和变量集合的只读权限。
- 是否能读取变量、样式、组件属性、实例覆盖、Auto Layout、约束、原型和注释。
- 是否存在多个主题、模式、品牌、平台或密度集合。
- 用户要求的是当前设计意图、运行实现，还是两者差异。

优先使用目的明确的设计工具连接器或 API。调用 Figma 工具时遵循当前环境要求的 Figma Skill；除非用户明确要求修复设计文件，否则保持只读。

## 采集顺序

1. 记录文件、分支、版本、页面、节点、库和采集时间。
2. 建立页面、流程、组件、变量集合和主题模式清单。
3. 提取变量类型、值、别名、模式、作用域和描述；保留库来源。
4. 提取组件 anatomy、variant 属性、合法组合、实例覆盖和嵌套依赖。
5. 检查 Auto Layout、约束、网格、容器行为、最小最大尺寸和内容适配。
6. 检查文本样式、实际字体、行高、字距、截断和本地化样例。
7. 检查原型连接、交互触发、动效、覆盖层、滚动和返回行为。
8. 检查设计注释、无障碍说明、Code Connect 或实现映射。
9. 获取关键节点截图，核对结构化属性与实际渲染是否一致。
10. 只提取任务范围内的页面和组件，不扫描无关团队内容。

## 证据分类

- 通过设计 API 直接读取的变量、尺寸、组件属性和模式标为 `measured`。
- 从设计画布截图或导出图取样的视觉值标为 `sampled`。
- 直接看到但无法取得精确属性的行为或结构标为 `observed`。
- 根据别名、重复实例或组件关系推导的规律标为 `inferred`。
- 为目标项目、平台或无障碍要求进行的改变标为 `adapted`。

每项仍需独立填写 `confidence` 和 `confidenceReason`。不要因为来源是设计文件就自动使用高置信度。

## 多来源权威策略

将来源角色分开：

| 来源 | 默认代表 |
|---|---|
| 设计文件 | 设计意图、组件契约和计划模式 |
| 代码与 token 文件 | 已声明的实现规则 |
| 运行页面或应用 | 当前版本的实际行为 |
| 截图或录屏 | 特定上下文的渲染与流程证据 |

不要默认任一来源永远优先。发现差异时：

1. 核对版本、分支、平台、主题、状态和发布时间。
2. 确认用户或项目是否已有权威来源策略。
3. 只在裁决会改变最终值时请求用户确认。
4. 未确认时并列记录 `design_intent`、`declared_implementation` 和 `runtime_observation`。
5. 将未裁决项写入 `design-spec.md` 的冲突清单，不生成确定 token 或代码映射。

## 降级

- 只能查看截图时，按截图证据处理，不把变量、组件语义或 Auto Layout 标为已验证。
- 缺少库权限时，记录不可解析的别名和组件依赖，不复制猜测值。
- 缺少指定节点时，请求最小节点范围；不要凭文件名称猜测目标页面。
- 设计文件与线上版本无法对应时，产物最多标为 `partial`，并分别说明各自覆盖范围。
